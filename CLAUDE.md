# Troop Tracker Mobile — Claude Code Reference

Troop Tracker Mobile is the iOS/Android app for [Troop Tracker](https://github.com/obsidianslicers/trooper-tracker),
the costuming club tracker. It wraps the tracker web app in a WebView and adds push
notifications, a native notification inbox, the app icon badge, and a few native screens.
It's set up for the Florida Garrison only for now.

---

## Tests are mandatory

**Every change comes with tests, in the same pull request.** No exceptions for "small" changes.

- New or changed behavior in `lib/` → add or update its unit/widget test in `test/`, mirroring
  the file's path (`lib/views/x.dart` → `test/views/x_test.dart`).
- A bug fix → first a test that fails without the fix.
- A change to startup, the WebView, notifications, or a user journey → add or update an e2e
  test in `integration_test/` (and the mock tracker in `tool/mock_tracker.dart` if the app
  calls something new).
- There's no coverage percentage to hit; test the behavior that matters. If code is hard to
  test, make it testable (inject the dependency) rather than skipping its tests.
- Before saying a change is done, run and pass:
  ```bash
  flutter test
  dart format --output=none --set-exit-if-changed .
  flutter analyze
  ```
  If something couldn't be run (e.g. e2e tests need an emulator), say so.

See [docs/TESTING.md](docs/TESTING.md) for the fakes and patterns to use.

## Architecture

Services → Controllers → Views. Full details: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

```
lib/
├── main.dart              # Entry point only; keep it tiny (unit tests can't reach it)
├── app.dart               # initializeServices() and TroopTrackerApp
├── config/                # AppConfig: tracker URL, internal domains, colors, urlFor()
├── models/                # Plain data classes
├── services/              # Plugins and network (FCM, inbox API, url_launcher, permissions)
├── controllers/           # State for views
├── views/                 # Screens
└── widgets/               # Reusable widgets
test/                      # Mirrors lib/; shared fakes in test/support/
integration_test/          # E2E tests against tool/mock_tracker.dart
tool/                      # coverage_report.dart, mock_tracker.dart
docs/                      # ARCHITECTURE, DEVELOPMENT, TESTING
```

- **Dependencies through the constructor**, with the real one as the default:
  `NotificationsController({NotificationApiService? api, ...})`. Tests pass fakes; production
  code passes nothing.
- **Business logic lives in the tracker, not here.** The app shows the tracker's pages; it
  doesn't reimplement them. Prefer a tracker change over native code that duplicates the site.
- Build tracker URLs with `AppConfig.urlFor(path)`, not by joining strings.
- The web app and the app talk through `window.__authState`, `window.__fcmToken` /
  `window.__onFcmTokenReady`, and `/api/push-notifications` with an `FCM-Token` header. Changing
  any of these needs the matching change in the tracker repo.

## Coding conventions

Full list: [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md#coding-conventions).

- Dart naming: `UpperCamelCase` types, `lowerCamelCase` members/variables, `snake_case.dart` files.
- Lines ≤ 100 characters (`dart format` enforces it); explicit types on public APIs.
- `unawaited(...)` around futures that are deliberately not awaited.
- Comments only for a non-obvious *why*.
- Never edit `lib/firebase_options.dart` (generated by `flutterfire configure`).
- Don't change `pubspec.lock` unless the change is about dependencies.

## Common commands

```bash
cp .env.example .env                 # once; tests and builds need a .env
flutter pub get
flutter run

flutter test                         # unit + widget tests
flutter test --coverage && dart run tool/coverage_report.dart   # what's untested
dart run tool/mock_tracker.dart 8080 # mock tracker for e2e tests
flutter test integration_test        # e2e (emulator; .env TRACKER_URL=http://10.0.2.2:8080/)

dart format .
flutter analyze
```

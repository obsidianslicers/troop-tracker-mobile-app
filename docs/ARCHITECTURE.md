# Architecture

Troop Tracker Mobile is a native shell around the [Troop Tracker](https://github.com/obsidianslicers/trooper-tracker)
web app. The tracker itself (sign-in, events, profiles) runs in a WebView; the app adds what a web
page can't do well: push notifications, a native notification inbox, the app icon badge, and a
few native screens.

The code follows a small layered structure, **Services → Controllers → Views**, with
dependencies passed in through constructors so every layer can be tested on its own.

---

## Directory structure

```
lib/
├── main.dart                 # Entry point: native splash, initializeServices(), runApp()
├── app.dart                  # initializeServices() and the TroopTrackerApp widget
├── firebase_options.dart     # Generated by `flutterfire configure`; never edit by hand
├── config/app_config.dart    # Tracker URL, internal domains, colors, urlFor()
├── models/                   # Plain data classes (PushNotification)
├── services/                 # I/O: Firebase Messaging, the inbox API, url_launcher, permissions
├── controllers/              # State for the views (ChangeNotifier where the UI listens)
├── views/                    # Screens: splash, main shell and its three tabs, error
└── widgets/                  # Small reusable widgets: bottom nav, loading bar, error panel
```

Tests mirror this layout under `test/`; see [TESTING.md](TESTING.md).

---

## Startup

1. `main()` keeps the native splash on screen and calls `initializeServices()`, which loads
   `.env`, starts Firebase, and starts push notification setup **without waiting for it**
   (on iOS the APNs token can take a long time; waiting would hang the splash).
2. `SplashView` removes the native splash, fades in the logo, and after 1.8 seconds replaces
   itself with `MainShellView`.
3. `MainShellView` creates the `WebviewController` and `NotificationsController` and shows three
   tabs in an `IndexedStack`, so the WebView keeps its page while the trooper switches tabs.

## Layers

### Config (`lib/config/app_config.dart`)

The one place for app-wide settings. `TRACKER_URL` and `INTERNAL_DOMAINS` come from `.env`.

| Member | What it is |
|--------|------------|
| `trackerUrl` | The tracker the WebView loads |
| `trackerDomain` | The tracker host's registrable domain (`test.fl501st.com` → `fl501st.com`) |
| `internalDomains` | Domains whose links stay in the app; everything else opens in the browser |
| `urlFor(path)` | The full tracker URL for a path such as `/events/42` |

### Models (`lib/models/`)

Plain Dart classes with no Flutter or service dependencies.

| File | Purpose |
|------|---------|
| `push_notification.dart` | One inbox entry from `GET /api/push-notifications` |

### Services (`lib/services/`)

Thin wrappers around plugins and the network. Static helpers (`abstract final class`) where
there is no state to inject; instances with constructor parameters where tests need a stand-in.

| File | Purpose |
|------|---------|
| `push_notification_service.dart` | FCM permission, token, and routing a tapped notification to its page |
| `notification_api_service.dart` | The tracker's inbox API, authenticated by the device's FCM token |
| `webview_service.dart` | Decides whether a URL stays in the WebView |
| `url_launcher_service.dart` | Opens a URL in the system browser |
| `permission_service.dart` | Camera and photo permissions for uploads |

### Controllers (`lib/controllers/`)

| File | Purpose |
|------|---------|
| `webview_controller.dart` | Owns the WebView: loading/error state, sign-in state, FCM token injection, link routing |
| `notifications_controller.dart` | The inbox: refresh, mark read, clear; keeps the icon badge in step |
| `settings_controller.dart` | App version and "Open in Browser" for the Settings tab |
| `splash_controller.dart` | The minimum splash time |

### Views and widgets

| File | Purpose |
|------|---------|
| `views/splash_view.dart` | The Flutter splash that follows the native one |
| `views/main_shell_view.dart` | App bar, bottom navigation, Android back handling |
| `views/tracker_view.dart` | The WebView, with pull to refresh; swaps to `ErrorView` on failure |
| `views/notifications_view.dart` | The inbox, or a sign-in prompt when signed out |
| `views/settings_view.dart` | Version, Clear Cache, Open in Browser |
| `views/error_view.dart` | Full-screen load error with Retry |
| `widgets/app_bottom_nav.dart` | Bottom navigation with the unread badge |
| `widgets/loading_overlay.dart` | The lightsaber loading bar |
| `widgets/retry_error_panel.dart` | Error message, Retry and Open in Browser buttons |

## How the app and the web app talk

| Direction | Mechanism |
|-----------|-----------|
| Web → app: sign-in state | The page sets `window.__authState = true/false`; the app reads it after every page load |
| App → web: FCM token | The app sets `window.__fcmToken` and calls `window.__onFcmTokenReady(token)`; the web app registers the device for the signed-in trooper |
| App → tracker API | `/api/push-notifications` with an `FCM-Token` header |
| Notification tap | The push's `url` data opens that page in the WebView |
| OAuth pop-ups | `window.open` is redirected into the same WebView so the session cookie survives |

On Android the WebView sends a plain mobile Chrome user agent, because OAuth providers block
sign-in forms in user agents marked as an embedded WebView.

---

## Links

Links to the tracker's domain, its subdomains, and `INTERNAL_DOMAINS` stay in the WebView.
Other top-level links open in the system browser; external iframes (e.g. YouTube embeds) load
in place.
